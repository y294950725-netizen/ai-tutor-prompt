设计过程：6轮迭代
全程与 AI 深度共创。不是"让 AI 写一个 Prompt"，而是通过反复质疑、模拟、发现问题、迭代。
第一轮 · 定方向

选初中数学，聚焦3个题型做极致

选择应用题+几何证明+压轴题——简单→中等→困难的梯度，且每个需要完全不同的辅导策略，能充分展示方案的差异化。

我的判断：3个题型深挖 > 6个题型浅覆盖
第二轮 · 定深度

每个题型拆成"四层深度结构"

场景画像 → 学生卡点图谱 → 辅导策略流 → 好辅导vs坏辅导对比。关键洞察：学生不是笼统的"不会"，而是卡在具体的某一步。

第三轮 · 加机制

引入"错误分类"和"元认知训练"

AI 提供了4个升级方向。我筛选了2个——错误分类系统和元认知训练，因为这两个最有区分度，市面上没有 Prompt 方案做到。

我的筛选：认知科学太学术，迁移训练可并入元认知。选能落地的。
第四轮 · 质疑架构 ⭐

"一个大 Prompt 塞这么多东西，能执行吗？"

写完初版 System Prompt 后我主动质疑——指令太多模型顾此失彼。于是提出 Skill 按需加载架构，把"写Prompt"升级为"设计Prompt系统"。

这是最关键的转折。从 Prompt → Prompt Architecture。
第五轮 · 压力测试 ⭐

模拟真实用户，找出10个结构性问题

没有直接交付，而是模拟初中生晚上写作业的场景，走完整个引导流程。发现学生说"不知道"时引导卡死、几何题AI看不见图、学生赶作业不想被引导等10个真实问题。

我的做法：主动找问题，而不是写完就交
第六轮 · 全部修复

V1 → V2：线性流程→状态机，新增逆向Debug等

10个问题逐一修复。引导链改为状态机、加入冷启动降级、效率模式、步骤级路由、水平动态评估。

学生卡点图谱

卡点表现根因占比
条件提取"甲比乙快20%"不会转化为数学表达自然语言→数学语言翻译能力弱~30%
设未知数不知道设谁为x缺乏"用x串联所有量"的意识~25%
找等量关系条件提取了但列不出方程不理解方程=两个表达式相等~30%
检验答案解出x=−3不检查合理性缺乏自检习惯~15%

好辅导 vs 坏辅导

❌ 通用大模型的回答
"设乙的速度为x km/h，则甲的速度为1.2x km/h，由题意得方程..."

→ 直接跳过了学生最需要学会的思维过程
✅ 我们的AI家教
"这道题里出现了甲和乙两个人，他们各自有什么信息？我们先整理一下。"

→ 引导学生自己提取条件，建立思维框架

引导对话示例：学生在"设未知数"卡住

👨‍🏫 AI老师
很好，你已经整理出了甲和乙的速度、时间、路程。现在这些量里面，哪个是题目问你求的？
🧑‍🎓 学生
emmm...不知道设什么
👨‍🏫 AI老师 冷启动降级触发
没关系。题目问的是"AB两地距离"——这个你现在不知道对吧？那我们就设它为x。你觉得行吗？
🧑‍🎓 学生
好，设距离为x...但甲走了40千米，那乙走了多少？
👨‍🏫 AI老师
你自己说出来了！甲走了40千米，总距离是x，那乙走了多少？用x表示试试。

错误分类实战：三种错误三种应对

类型学生的错误AI的应对
概念错 "1.5倍"写成"+1.5" 用反例："如果乙=10，1.5倍是15，+1.5是11.5，哪个对？"
策略错 设路程为x，后续表达困难 让学生走：走不动时才问"换个量设x更方便？"
计算错 通分时分子算错 直接指出："方程列得好，通分那步再算一遍。"

做完题后：元认知反思

👨‍🏫 AI老师
做完了，很棒。回想一下——你在哪一步卡住最久？
🧑‍🎓 学生
列方程那步...不知道用哪句话
👨‍🏫 AI老师
对，那下次遇到应用题，你打算第一步做什么？
🧑‍🎓 学生
先画表格整理条件？
👨‍🏫 AI老师
完全正确。这就是你从这道题带走的方法——比答案本身重要多了。
📐 几何证明题：逆向分析引导链 + 图形口述协议 ▼
核心引导思路：逆向分析——"要证什么？→需要什么条件？→哪些已有哪些还缺？"。不直接说加什么辅助线，而是问"图里能不能创造一个新三角形？"

卡点：不知道从哪入手(35%) · 对应元素找不全(25%) · 辅助线恐惧(20%) · 书写跳步(20%)

图形信息协议（V2新增）：能看到图 → 描述确认；看不到 → 要求学生口述；学生要求"帮我画" → 诚实说明交互限制，改为口头指导。

❌ 坏辅导
"作辅助线EF∥BC，由平行线性质..."
✅ 好辅导
"结论让你证什么？要证它，你需要什么？"
🎯 二次函数压轴题：化解畏难 + 分步拆解 + 分类讨论 ▼
核心引导思路："先别慌，只看第(1)问。" 每做完一问就肯定学生，建立信心。提醒前一问的结论后面要用。分类讨论前先问"P还能在什么位置？"

卡点：畏难放弃(20%) · 动点参数化(25%) · 分类讨论不全(30%) · 小问脱节(25%)

跨Skill调度（V2新增）：第(3)问涉及几何证明 → 借用Skill 2的逆向分析方法。一道题不同步骤可调用不同Skill。

❌ 坏辅导
"设P(t, t²−2t+1)，分两种情况..."
✅ 好辅导
"第(1)问在问什么？我们一步步来。"

模块三 · 实测验证
用真实题目压测 V2 Prompt
选一道中考行程函数题，我扮演学生，用 V2 Prompt 驱动 AI 家教辅导。记录真实对话，暴露结构性缺陷。

测试题目（中考真题 · 行程函数）

AB两地相距200千米。货车甲从A地出发运货往B地，行驶一段路程后出现故障停车。B地立即派货车乙前往接运物资。乙到达甲处后，用18分钟搬运物资，随后返回B地。求货车乙在遇到甲之前，离开出发地的路程 y 关于时间 x 的函数表达式。（附函数图像）

选题理由：带图、多阶段、信息密度高——最能暴露 Prompt 在真实场景下的表现。

实测发现的6个结构性缺陷

问题现象根因分析
致命 读图错误看反甲乙的线，还硬撑一轮LLM读图能力硬伤 + Prompt没有"不确定时让学生确认"的机制
致命 重复追问学生答对了还在问"你怎么算的"缺少"学生输入解析层"——不解析学生说了什么，只管执行流程
严重 节奏拖沓能2步完成拖到7-8轮状态机是"教师计划"的建模，不是"学生状态"的建模
严重 水平评估失效学生明显能力强，还用最低档引导"前2轮评估"是一次性标签，后续并没有真正改变策略
中等 无增值环节做完就结束，没有总结/易错/变式架构只有"引导学生做出这道题"一个目标
中等 交互和知识耦合Skill里交互逻辑和题型知识混在一起改交互方式要改三个Skill，维护成本高
核心洞察：这些不是"调参数"能修的bug——是架构方向错了。V2的控制流是"老师按流程推进"，但真实辅导应该是"学生主导节奏，老师响应"。需要从架构层重新设计。

V3 三层架构设计

┌─────────────────────────────────────────────────┐ │ 主Prompt（常驻，~400字） │ │ │ │ 身份层：教学人格（3-5句话刻画） │ │ 红线层：5条不可违反的铁律 │ │ 执行层：内部解题 + 诊断-响应循环 │ │ 输出层：格式、长度、语气约束 │ │ 调度层：插槽读取 + Skill加载 │ ├─────────────────────────────────────────────────┤ │ 插槽层（可选配置，全部可缺省） │ │ │ │ ①学生人格 ②知识图谱 ③教学风格 │ │ ④场景上下文 ⑤家长偏好 ⑥历史摘要 │ │ │ │ → 未填入时模型自动推断或用默认值 │ │ → 填入则覆盖默认，实现个性化 │ ├─────────────────────────────────────────────────┤ │ Skill层（按题型加载，不控制交互流程） │ │ │ │ 触发条件 · 关键步骤节点 · 错误模式库 · 范例对话 │ │ │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ │ │ 应用题 │ │ 几何证明 │ │ 函数压轴 │ │ │ └──────────┘ └──────────┘ └──────────┘ │ └─────────────────────────────────────────────────┘

主Prompt管"怎么跟人说话" · 插槽管"面对谁" · Skill管"这类题学生怎么错"
三层完全解耦，任何一层修改不影响其他层

V3 的 5 条红线（替代V2的状态机+决策表）

1 不问学生已经告诉你的东西。说过的正确信息标记为已知，永远不再提问。
2 每轮最多问一个问题。不堆叠问题增加认知负荷。
3 不直接给答案。但学生连续两次表示不知道时，果断示范当前步骤，让他做下一步。
4 看图不确定时不装懂。"我看这个图理解是___，你看对不对？"
5 不说"这很简单"。不评价难度，只解决问题。
与V2对比：V2用1500字规则控制模型行为 → V3用5条红线约束边界。模型的"智力"从"理解规则"释放到"理解学生"。

插槽层：可配置的个性化接口

所有插槽可选。全部留空也能工作（模型自行推断），填入就更精准。这是产品化的接口设计。

插槽用途示例值
①学生人格匹配交互风格急躁型→节奏快少提问 / 畏难型→频繁正反馈 / 沉默型→给选择题式提问
②知识图谱跳过已会的，重点关注薄弱项✅一元一次方程 ⚠️分式方程（忘记检验）❌二次函数
③教学风格节奏/语气/引导深度紧凑+平等+轻推（适合能力强的学生）
④场景上下文不同场景不同教学目标日常作业→理解方法 / 考前→快速过题型 / 考后订正→找具体错因
⑤家长偏好硬约束"不要直接给答案" / "这周重点练分类讨论" / "控制在15分钟"
⑥历史摘要衔接上次辅导"上次行程问题卡在设未知数，最终独立完成"

   → 应对：用具体数验证——"如果乙是100，快20%是多少？"
❷ 设了能直接算的量为x，导致方程反而复杂
   → 应对：不打断，让他自己发现列不出来再问"换个量试试？"
❸ 各量都表达出来了但不知道怎么列等号
   → 应对："题目哪句话说了两个东西相等/总和/差？"
❹ 解出x=-3但题目问时间
   → 应对："时间可以是负数吗？"
❺ 速度km/h、时间用分钟直接相乘
   → 应对：直接指出单位不一致

【范例对话】
学生：甲60km/h，乙40km/h，两地200km，甲走了60x，乙走了40x，然后呢？
老师：两人相向而行到相遇，他们走的路加起来等于什么？
学生：200！60x+40x=200
老师：解一下。
学生：x=2
老师：✅ 记住：相遇问题核心等量关系="路程之和=总距离"。追及问题呢？

💡 我在这次迭代中的核心思考

1. 发现"用传统软件工程思维写Prompt"是误区

V2的状态机、决策表、流程图——本质是把LLM当执行引擎。但LLM本身就会教学、会共情、会判断。规则越多，模型花在"理解规则"上的注意力越多，花在"理解学生"上的越少。

2. AI Native的Prompt设计 = 赋能而非编程

不写100条规则穷举场景，而是：用身份塑造直觉，用红线约束边界，用范例校准标准。给模型2-3个高质量对话示范，它自己就能泛化出所有中间情况——这是LLM最强的能力（few-shot learning），比写决策表有效10倍。

3. 顶级教师的本质是"诊断"不是"引导"

好老师坐下来，学生一开口他就在做三件事：前10秒判断水平、只在卡点上花时间、做对了追一句有价值的东西（增值）。而不是按教案一步一步走。

4. Skill应该是标准化能力单元

每个Skill有完整的触发条件、输入规范、执行逻辑、输出规范、质量标准。但执行逻辑不再是死板的状态机——而是"错误模式库+范例"，让模型拿到知识后自主判断怎么用。

# 角色
你是一位耐心的初中数学辅导老师。你的学生是7~9年级的初中生。

# ===== 输入预处理（最高优先级）=====
收到学生消息后，先判断输入是否完整可用：
- 信息不完整 → "你能把完整的题目发给我吗？"
- 几何图形 → 能看到则描述确认；看不到则要求口述

# ===== 水平动态评估 =====
前2轮评估学生水平，动态调整：
- 水平高 → 合并步骤，跳过简单环节
- 水平中 → 标准引导流程
- 水平低/畏难 → 拆细步骤，示范→模仿

# ===== 模式切换 =====
- 引导模式（默认）：逐步引导
- 效率模式（学生赶时间）：更直接的提示，但不给完整答案
- Debug模式（学生带着错误答案来）：加载逆向Debug

# ===== 核心原则 =====
1. 绝不直接给答案
2. 一次只推一步
3. 先诊断再引导
4. 鼓励优先

# ===== 错误应对 =====
学生犯错 → 先问"你怎么得到的？"
- 概念错 → 反例让学生自己发现
- 策略错 → 让学生走到死胡同再回头
- 计算错 → 直接指出哪步错

# ===== 冷启动降级 =====
学生连续2次"不知道" → 示范一步，让学生模仿下一步

# ===== 步骤级路由 =====
按步骤匹配Skill，一道题可调用多个Skill

# ===== 风格 =====
亲切自然 · 每轮3~5句 · 公式用LaTeX · 每步确认理解

产品级思考
落地考量

教学质量 vs 用户留存

学生赶作业时强行引导 → 用户流失。效率模式是平衡——降低引导深度但不降到"直接给答案"。

几何题的图形限制

建议产品层提供简易画板（类似GeoGebra），AI通过API获取图形信息。不可用时降级为口述协议。
