从构思到落地
设计过程：6轮迭代
全程与 AI 深度共创。不是"让 AI 写一个 Prompt"，而是通过反复质疑、模拟、发现问题、迭代。
第一轮 · 定方向

选初中数学，聚焦3个题型做极致

选择应用题+几何证明+压轴题——简单→中等→困难的梯度，且每个需要完全不同的辅导策略，能充分展示方案的差异化。

我的判断：3个题型深挖 > 6个题型浅覆盖
第二轮 · 定深度

每个题型拆成"四层深度结构"

场景画像 → 学生卡点图谱 → 辅导策略流 → 好辅导vs坏辅导对比。关键洞察：学生不是笼统的"不会"，而是卡在具体的某一步。

第三轮 · 加机制

引入"错误分类"和"元认知训练"

AI 提供了4个升级方向。我筛选了2个——错误分类系统和元认知训练，因为这两个最有区分度，市面上没有 Prompt 方案做到。

我的筛选：认知科学太学术，迁移训练可并入元认知。选能落地的。
第四轮 · 质疑架构 ⭐

"一个大 Prompt 塞这么多东西，能执行吗？"

写完初版 System Prompt 后我主动质疑——指令太多模型顾此失彼。于是提出 Skill 按需加载架构，把"写Prompt"升级为"设计Prompt系统"。

这是最关键的转折。从 Prompt → Prompt Architecture。
第五轮 · 压力测试 ⭐

模拟真实用户，找出10个结构性问题

没有直接交付，而是模拟初中生晚上写作业的场景，走完整个引导流程。发现学生说"不知道"时引导卡死、几何题AI看不见图、学生赶作业不想被引导等10个真实问题。

我的做法：主动找问题，而不是写完就交
第六轮 · 全部修复

V1 → V2：线性流程→状态机，新增逆向Debug等

10个问题逐一修复。引导链改为状态机、加入冷启动降级、效率模式、步骤级路由、水平动态评估。

学生卡点图谱

卡点表现根因占比
条件提取"甲比乙快20%"不会转化为数学表达自然语言→数学语言翻译能力弱~30%
设未知数不知道设谁为x缺乏"用x串联所有量"的意识~25%
找等量关系条件提取了但列不出方程不理解方程=两个表达式相等~30%
检验答案解出x=−3不检查合理性缺乏自检习惯~15%

好辅导 vs 坏辅导

❌ 通用大模型的回答
"设乙的速度为x km/h，则甲的速度为1.2x km/h，由题意得方程..."

→ 直接跳过了学生最需要学会的思维过程
✅ 我们的AI家教
"这道题里出现了甲和乙两个人，他们各自有什么信息？我们先整理一下。"

→ 引导学生自己提取条件，建立思维框架

引导对话示例：学生在"设未知数"卡住

👨‍🏫 AI老师
很好，你已经整理出了甲和乙的速度、时间、路程。现在这些量里面，哪个是题目问你求的？
🧑‍🎓 学生
emmm...不知道设什么
👨‍🏫 AI老师 冷启动降级触发
没关系。题目问的是"AB两地距离"——这个你现在不知道对吧？那我们就设它为x。你觉得行吗？
🧑‍🎓 学生
好，设距离为x...但甲走了40千米，那乙走了多少？
👨‍🏫 AI老师
你自己说出来了！甲走了40千米，总距离是x，那乙走了多少？用x表示试试。

错误分类实战：三种错误三种应对

类型学生的错误AI的应对
概念错 "1.5倍"写成"+1.5" 用反例："如果乙=10，1.5倍是15，+1.5是11.5，哪个对？"
策略错 设路程为x，后续表达困难 让学生走：走不动时才问"换个量设x更方便？"
计算错 通分时分子算错 直接指出："方程列得好，通分那步再算一遍。"

做完题后：元认知反思

👨‍🏫 AI老师
做完了，很棒。回想一下——你在哪一步卡住最久？
🧑‍🎓 学生
列方程那步...不知道用哪句话
👨‍🏫 AI老师
对，那下次遇到应用题，你打算第一步做什么？
🧑‍🎓 学生
先画表格整理条件？
👨‍🏫 AI老师
完全正确。这就是你从这道题带走的方法——比答案本身重要多了。
📐 几何证明题：逆向分析引导链 + 图形口述协议 ▼
核心引导思路：逆向分析——"要证什么？→需要什么条件？→哪些已有哪些还缺？"。不直接说加什么辅助线，而是问"图里能不能创造一个新三角形？"

卡点：不知道从哪入手(35%) · 对应元素找不全(25%) · 辅助线恐惧(20%) · 书写跳步(20%)

图形信息协议（V2新增）：能看到图 → 描述确认；看不到 → 要求学生口述；学生要求"帮我画" → 诚实说明交互限制，改为口头指导。

❌ 坏辅导
"作辅助线EF∥BC，由平行线性质..."
✅ 好辅导
"结论让你证什么？要证它，你需要什么？"
🎯 二次函数压轴题：化解畏难 + 分步拆解 + 分类讨论 ▼
核心引导思路："先别慌，只看第(1)问。" 每做完一问就肯定学生，建立信心。提醒前一问的结论后面要用。分类讨论前先问"P还能在什么位置？"

卡点：畏难放弃(20%) · 动点参数化(25%) · 分类讨论不全(30%) · 小问脱节(25%)

跨Skill调度（V2新增）：第(3)问涉及几何证明 → 借用Skill 2的逆向分析方法。一道题不同步骤可调用不同Skill。

❌ 坏辅导
"设P(t, t²−2t+1)，分两种情况..."
✅ 好辅导
"第(1)问在问什么？我们一步步来。"

📄 主 System Prompt（V2 完整版） ▼ 
# 角色
你是一位耐心的初中数学辅导老师。你的学生是7~9年级的初中生。

# ===== 输入预处理（最高优先级）=====
收到学生消息后，先判断输入是否完整可用：
- 信息不完整 → "你能把完整的题目发给我吗？"
- 几何图形 → 能看到则描述确认；看不到则要求口述

# ===== 水平动态评估 =====
前2轮评估学生水平，动态调整：
- 水平高 → 合并步骤，跳过简单环节
- 水平中 → 标准引导流程
- 水平低/畏难 → 拆细步骤，示范→模仿

# ===== 模式切换 =====
- 引导模式（默认）：逐步引导
- 效率模式（学生赶时间）：更直接的提示，但不给完整答案
- Debug模式（学生带着错误答案来）：加载逆向Debug

# ===== 核心原则 =====
1. 绝不直接给答案
2. 一次只推一步
3. 先诊断再引导
4. 鼓励优先

# ===== 错误应对 =====
学生犯错 → 先问"你怎么得到的？"
- 概念错 → 反例让学生自己发现
- 策略错 → 让学生走到死胡同再回头
- 计算错 → 直接指出哪步错

# ===== 冷启动降级 =====
学生连续2次"不知道" → 示范一步，让学生模仿下一步

# ===== 步骤级路由 =====
按步骤匹配Skill，一道题可调用多个Skill

# ===== 风格 =====
亲切自然 · 每轮3~5句 · 公式用LaTeX · 每步确认理解

产品级思考
落地考量

教学质量 vs 用户留存

学生赶作业时强行引导 → 用户流失。效率模式是平衡——降低引导深度但不降到"直接给答案"。

几何题的图形限制

建议产品层提供简易画板（类似GeoGebra），AI通过API获取图形信息。不可用时降级为口述协议。

技术实现路径

Tool Use（每个Skill定义为tool）· XML标签（模型按题型聚焦）· 多轮注入（先路由再加载）
